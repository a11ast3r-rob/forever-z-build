# 3) The expansion rule

Every new piece of information should land in one of four buckets:

## A — Fact
Example:
> “Front wheels are 19×9 +47 OEM RAYS.”

Action:
- Add to current-car spec.
- Add photo/evidence.
- Stop treating that item as unknown.

## B — Issue
Example:
> “Clutch pedal sticks after driving.”

Action:
- Add to issues list.
- Assign STOP / FIX NOW or DRIVE / MONITOR.
- Expand the relevant diagnosis / repair section.

## C — Existing modification
Example:
> “The car already has aftermarket coilovers.”

Action:
- Identify brand / model / settings.
- Decide KEEP / SERVICE / REPLACE.
- Recalculate the build plan around what is actually installed.

## D — New build decision
Example:
> “We picked a wrap color.”

Action:
- Update DECISIONS.
- Update relevant plan.
- Add dated BUILD_LOG entry.
- Update site.

# 4) Expansion branches

## If the car already has good aftermarket wheels
Create:
- wheel identification record
- exact specs
- tire age / condition
- clearance notes

Then decide:
- keep temporarily
- sell
- use as spare set
- replace immediately

The 57DR plan can wait if the current wheel/tire package is genuinely good.

---

## If the car has Sport brakes / upgraded brakes
Add:
- caliper identification
- rotor size
- pad type
- wheel-clearance requirement

Then re-verify 57DR brake clearance before ordering.

---

## If the suspension is stock
Proceed with:
- stock ride-height measurements
- stock alignment baseline
- air-suspension package planning

## If it has lowering springs
Add:
- spring brand / part number
- shock condition
- current drop
- rubbing/alignment notes

Then decide whether to:
- run temporarily
- return to stock
- move directly to air

## If it has coilovers
Add:
- brand / model
- spring rates if known
- damper settings
- ride height
- top mounts
- rear true-style vs divorced layout

Then evaluate resale/reuse value before ordering air hardware.

---

## If clutch / CSC symptoms exist
Expand a dedicated **Clutch & Hydraulics** section with:
- symptom log
- fluid condition
- hot vs cold behavior
- engagement behavior
- shop diagnosis
- repair parts
- final outcome

This becomes a reliability phase before suspension/audio work.

---

## If oil pressure is questionable
Expand a dedicated **Engine Health** section.

Record:
- shop measurements
- oil temp at measurement
- oil used
- warning signs
- diagnosis
- repair decision

Do not bury a possible engine-health problem under mods.

---

## If oil temperature is normal for actual use
Keep oil cooler in WATCH status.

## If oil temperature is repeatedly too high for actual use
Promote cooling to an active build module:
- thermostatic sandwich plate
- cooler size
- mounting
- hose routing
- protection
- post-install temperature comparison

---

## If existing audio wiring is clean
Integrate around it.

## If existing audio wiring is hacked
Create an **Electrical Cleanup** phase before amps/subs:
- remove unsafe splices
- correct fuse placement
- verify wire gauge
- rebuild grounds
- document routing

---

## If the body is clean
Wrap plan can stay simple:
- correction
- minor chip repair
- prep
- wrap

## If the body has dents / bad paint / previous repairs
Create a **Body Prep** phase:
- PDR
- bumper repair
- cracked plastic repair
- sanding / paint stabilization where required
- panel alignment
- wrap readiness sign-off

# 8) Decision hierarchy

Whenever we learn something new, use this order:

1. **Safety**
2. **Reliability**
3. **Known condition**
4. **Measurements**
5. **Driveability**
6. **Fitment**
7. **Performance support**
8. **Audio / comfort**
9. **Exterior**
10. **Cosmetic finishing details**

This does not mean we cannot have fun early. It means expensive decisions should not outrun the facts.

---

# 9) What will trigger the next major site revision

The next major revision should happen when **any one** of these is true:

- The current car is purchased.
- A different car replaces it as the active candidate.
- We receive a PPI / inspection report.
- We learn the exact installed suspension.
- We learn the exact wheel / tire setup.
- We learn the exact audio hardware.
- A major mechanical issue is discovered.
- A major build purchase is actually made.

At that point, the site moves from **plan-first** to **evidence-first**.
